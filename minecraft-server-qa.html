MC-001HighPlayers cannot connect to Simple Voice Chat

Minecraft 1.20.1 Forge · Simple Voice Chat · Status: Fixed

Steps to reproduce

  1. Start the server and join with the modpack client.
  2. Join from a player machine outside my local network.
  3. Check the voice chat status in game.

Expected

Players join the game and can talk to each other by voice.

Actual

Players could join the game but voice chat did not connect. The server log showed: “Port Failed to Connect to Simple Voice Chat”.

Root cause

Voice chat uses its own network port, separate from the main game connection. Players could reach the game through the server’s tunnel but could not reach the voice chat port, so they could play but not talk.

Fix

Created a separate Playit.gg tunnel just for the voice chat port, alongside the Minecraft server tunnel, and changed the host address in the Simple Voice Chat config to the tunnel’s address so players connect through it. The port number is left out on purpose.

Verification

Players on the server tested voice chat after the change.

MC-002HighClient and server files do not match, causing a join failure

Modpack: Cozy Lunchtime 1.20.1 · Status: Fixed

Steps to reproduce

  1. Install the modpack on the client.
  2. Try to join the server.

Expected

The client joins with no errors.

Actual

The connection was refused because the client and server game files did not match. The log said Field Guide 1.20.1 was not up to date with Field Guide 1.20.1, so the two copies were out of sync.

Root cause

The Field Guide config did not match what the server expected. The EXP values did not exist in the config and the lens craftable setting was false, so the two sides disagreed.

Fix

Edited fieldguide1.20.1.config so it matched the server:

  • Changed “lens craftable” from false to true.
  • Added the Field Guide EXP values, which did not exist before, to match the server’s EXP levels for a different mod: Exploring New Terrain 20, Discovering New Mobs 5, Discovering New Plants 2.

Verification

After the change, players joined without issues.

MC-003MediumServer falls behind when one player explores new terrain

Cozy Lunchtime 1.20.1 with Create · Status: Partly mitigated, still happens at times

Steps to reproduce

  1. One player travels far from spawn into terrain nobody has explored.
  2. Watch the server’s TPS and log while they travel.

Expected

TPS stays near 20.

Actual

In one case a player explored about 7,000 blocks and the server fell about 10 ticks behind. The log says the server can’t keep up: about 10 ticks behind, 530 ms.

Notes

The lag appears when chunks are being loaded for the explorer, and Create adds to the server load. It does not appear with several players online who are not exploring.

Mitigation tried

Lowered the server’s RAM allocation from 11 GB to 8 GB to leave more room for the rest of the machine. The server now lags less but still falls behind from time to time.

Test plan for the server

What I check before and after every update.

Scope
Joining, voice chat, mod compatibility, world save and restart, server performance, and updates to the modpack.

Server starts with no errors in the log, a client joins, and voice chat connects.
Regression
Re-run all test cases below after any mod, modpack, or config change.
Exploratory
Play for 30 to 45 minutes trying odd inputs, such as relogging fast, crossing chunk borders, and using many mod items at once.
Exit criteria
No open High bugs and all test cases run on the current version.
Severity
High: players cannot join or a core feature fails. Medium: a feature fails but there is a workaround. Low: cosmetic.

What I learned

Both bugs looked like “the server is broken” to players but had different causes: one in the network path and one in file versions. Reading the logs and changing one thing at a time found each cause faster than guessing. I now compare client and server versions before anything else when a join fails.

The lag only showed up when a single player explored new terrain, so I now test with one player exploring as well as several players online. Checking one scenario was not enough to call performance fine.
